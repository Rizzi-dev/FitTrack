# AGENTS.md: FitTrack (app)

App mobile do FitTrack (Expo SDK 52, Expo Router 4, TypeScript strict). Repo irmão: a API em `../fittrack-api/fittrack-api`.

## Regras obrigatórias para agentes e devs

Estas regras valem para qualquer pessoa ou agente de IA trabalhando neste repo e se sobrepõem a qualquer padrão da ferramenta.

### Antes de tocar no código
1. **Sempre leia o SDD primeiro.** No mínimo: `sdd/README.md`, `sdd/memory/*.md`, a task e a spec relacionadas. Sem task ligada a uma spec, não há mudança de comportamento.
2. **Nunca assuma contexto.** Se algo não está no código nem no `sdd/`, não existe: pergunte ou verifique (leia o arquivo, rode o comando, consulte a doc oficial). Não invente endpoints, campos, regras, versões nem decisões.

### Fonte da verdade
3. **O código é a fonte da razão e da verdade.** Se o `sdd/` diverge do código, o código descreve o que o sistema faz. Corrija o `sdd/` para refletir o código; se o código estiver errado em relação a uma spec aprovada, abra uma task para corrigir o código e registre a divergência. Nunca "corrija" uma divergência em silêncio.
4. **Todo conhecimento importante vive em arquivos do `sdd/`** e deve ser reproduzível por qualquer dev ou agente que clone o repo. Nada de decisão só no chat, na memória de uma ferramenta ou na cabeça de alguém. Decisão vira ADR, fato não óbvio vira `memory/`, sessão de trabalho vira `logs/`.

### Ao escrever código
5. **Código limpo e reutilizável.** Nomes claros, funções pequenas com uma responsabilidade, sem duplicação: extraia e reutilize o que já existe antes de criar algo novo. Siga `sdd/memory/convencoes.md`.
6. **Sem comentários desnecessários ou excessivos.** O código deve se explicar. Comente apenas o *porquê* não óbvio (uma restrição externa, um contorno de bug). Nunca comente o *o quê*, nunca deixe código comentado, nunca narre a mudança ("adicionado X", "agora usa Y").

### Ao terminar
7. **Sempre atualize o SDD** na mesma mudança: status da task e da spec, índices, `memory/estado-atual.md`, um log em `sdd/logs/` e ADR para decisões novas.
8. **Sempre deixe o projeto melhor do que encontrou.** Corrija pequenos problemas no caminho (nome ruim, import morto, doc desatualizada); o que for maior vira task no `sdd/tasks/` em vez de ficar esquecido.

### Git e PRs
9. **Sem co-autoria nos commits.** Não adicione `Co-Authored-By` nem qualquer trailer de autoria de IA.
10. **Sem "Generated by Claude"** (ou qualquer assinatura de ferramenta/IA) em PRs, commits, código ou docs.

## Onde está cada coisa
